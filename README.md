# maps-planning-she

해외 도시 리스트(`260804_해외국가_도시_리스트`)의 **일본 항목이 일본 행정구역을 얼마나 덮고 있는지** 분석한 결과와, 그 결과를 47개 도도부현 폴리곤 지도로 렌더링한 페이지.

> 내부 자료 기반이므로 private 저장소로 유지한다. 공개 전환 시 geoCode·도시 카탈로그가 그대로 노출된다.

## 보는 방법

```
open index.html
```

빌드 없이 바로 열리는 단일 파일이다. 지오메트리·스타일·스크립트가 모두 인라인되어 있어 외부 요청이 없다. 라이트/다크 테마를 지원하며 우상단 버튼으로 전환한다.

## 결론

"몇 %를 커버하나"는 **어느 계층을 분모로 두느냐에 따라 2%에서 66%까지** 달라진다. 세 숫자를 함께 봐야 한다.

| 기준 | 커버 | 전체 | 비율 |
| --- | --- | --- | --- |
| 광역 · 도도부현 (한국 17개 시·도 대응) | 24 | 47 | **51.1%** |
| 인구 가중 (커버된 도도부현 인구 합) | 8,246만 | 12,456만 | **66.2%** |
| 기초 · 시정촌 (한국 226개 시·군·구 대응) | 35 | 1,718 | **2.0%** |
| 정령지정도시 | 13 | 20 | **65%** |

일본의 **'지방(地方)'은 행정구역이 아니다.** 우리나라 도 단위가 아니라 "수도권 / 영남권" 같은 권역 개념이라 커버리지 지표로 쓸 수 없다. 도 단위에 대응하는 것은 도도부현이다.

## 발견

- **편중.** 커버된 24곳 중 2개 이상 항목을 가진 곳은 5곳뿐이다 — 홋카이도 7, 오이타 4, 가나가와·후쿠오카·나가사키 2. 나머지 19곳은 1개씩이다.
- **혼슈 중앙부가 통째로 비어 있다.** 나가노·기후·이시카와·도야마·니가타. 지도에서 가장 넓은 회색 덩어리이며, 가나자와·다카야마·시라카와고·마쓰모토 등 실수요가 있는 목적지가 여기 있다.
- **도호쿠 6개 현에 센다이 하나.**
- **수도권에서 사이타마·지바 누락.** 둘 다 인구 600만 이상. 특히 지바는 나리타 공항과 도쿄 디즈니리조트를 품고 있다.
- **정령지정도시 7곳 누락** — 사이타마, 지바, 가와사키, 사가미하라, 니가타, 하마마쓰, 사카이.

## 상위 단위 대체가 불가능한 이유

원본 리스트의 `구분` 컬럼은 값이 `국가` / `도시` **두 가지뿐**이다. 일본 37행은 국가 1행 + 도시 36행이고 **도도부현 행은 0개**다. 커버된 24개 현조차 상위 행 없이 시 단위만 들어가 있다. 따라서 미커버 현은 대체할 상위 행이 없어 국가(일본)로 바로 폴백하며, 이건 실질적 커버리지가 아니다.

대체 전략을 쓰려면 `구분`에 `광역` 계층을 추가하고 47개 도도부현 행을 채워야 한다. 다만 그렇게 해도 검색 수요가 현 이름이 아니라 도시 이름으로 발생하는 케이스(시라카와고, 가나자와)는 해결되지 않으므로, 도시 행 추가는 별개 작업이다.

## 재생성

```bash
cd scripts
curl -o japan.geojson https://raw.githubusercontent.com/dataofjapan/land/master/japan.geojson
python3 build_geo.py 0.006 0.0012   # -> japan_map.json  (단순화 + 투영 + SVG path)
python3 build_html.py               # -> japan_coverage.html  (본문 조각)
python3 build_standalone.py         # -> index.html  (독립 문서)
mv index.html ../
```

의존성 없음(표준 라이브러리만). `build_geo.py`는 실행 시 검증 결과를 출력한다 — 인셋 박스 충돌, 라벨-마커 간격, 라벨 근접쌍, 도도부현 누락.

커버 도시 목록과 인구 수치는 `scripts/build_geo.py`의 `PREF` / `CITIES` 딕셔너리에서 수정한다.

## 데이터 출처와 한계

- **폴리곤** — [dataofjapan/land](https://github.com/dataofjapan/land) `japan.geojson` (47 features, MultiPolygon). RDP ε=0.006°로 단순화, 면적 0.0012°² 미만 도서 생략.
- **투영** — 등거리 원통도법, 경도에 cos(중위도) 압축. 오키나와는 경도 122~131°에 퍼져 있어 본토와 같은 축척에 넣으면 지도가 뭉개지므로 별도 축척 인셋으로 분리했다.
- **아마미 군도(가고시마현) 생략** — 위도 27~28°까지 내려가 본토 지도 범위를 세로로 늘려버린다. 가고시마현 자체는 커버로 집계된다.
- **인구는 추정치** — 2023년 기준 도도부현 추계 반올림값의 합이므로 총계가 실제(약 1억 2,380만)와 수십만 단위 차이가 난다. 66.2%는 정확값이 아니다.
- **시정촌 분모 1,718** = 시 792 + 정 743 + 촌 183. 도쿄 23특별구 제외.
- **오키나와 항목의 계층이 모호하다.** geoCode `JP191298221`, 지역명 "일본 오키나와". 시 단위인지 현 단위인지 데이터만으로 판정되지 않아 기초자치단체 집계(35)에서는 제외하고 광역 커버에는 포함했다.

## 지도 인코딩

- **색 농도** = 해당 도도부현의 도시 항목 수. 0은 중립 회색. 순차 단일 색상 램프이며 다크 모드에서는 방향을 뒤집는다(항목이 많을수록 밝음).
- **주황 점** = 실제 도시 항목 위치 36개. 크기 인코딩과 채널을 분리하기 위해 다른 색상을 쓴다.
- **직접 라벨**은 항목 2개 이상인 5곳에만. 24곳 전부에 숫자를 넣으면 마커와 엉킨다. 라벨 좌표는 폴리곤 내부에서 경계·마커 양쪽으로부터 가장 먼 지점을 격자 탐색으로 구한다.
- **`미커버 23개 지역 강조`** 토글은 사선 해칭을 덧씌운다. 색각 이상·인쇄 대응 보조 인코딩이다.

색상은 대비·색각 검증을 통과한 값이다. 0값 회색과 최저 단계 파란색은 정상시야 ΔE 19.7로 분리했다(15 미달이면 인접 시 구분이 어렵다).
